- **A security report from the build pipeline, and the README sections that point to it** (2026-11-06, nightly scan): coop's only workflow is `.github/workflows/planning-files.yml`. No pipeline runs `govulncheck` or scans the image, and the README has no "Security checks" or "Trace propagation" section, though the nightly scan is told to read both. Each night the scan runs `govulncheck ./...` itself, so a vulnerability shows up only once a day and not on the change that brings it in. Proposed: a `security` workflow that runs `govulncheck` (and an image scan once #2 publishes one) on push and PR and keeps its report as an artifact, plus a README "Security checks" section naming it and a "Trace propagation" section summarising `decisions/trace-propagation-2026-11-03.md` as coop applies it (STATE.md has it today). Related: tacplus-dev/fleet-seatrials#38 (its `security.yml`), the platform roadmap's nightly scans (tacplus-dev/looper#49). Updated 2026-11-12 (nightly scan): the looper's build now runs the deterministic checks (looper-scan: govulncheck, osv-scanner, gosec, gitleaks, semgrep, trivy and others) and keeps `security/summary.md` and `findings.json` per run. So what is left here is the README "Security checks" and "Trace propagation" sections, which still do not exist. Two things would make that report more useful for coop. First, of its 466 findings, 465 are in the generated, uncommitted `tacplus/` tree (all 239 HIGH gosec failures and all 3 gitleaks "secrets", which are test fixtures in `tacplus/chassis/collection/page_behavior_test.go` and `tacplus/chassis/logger/logger_security_test.go`). The only finding in coop's own code is gosec G703 at `cmd/coop/main.go:130`. Scoping the checks to coop's sources, or reporting generated-code findings to tacplus, would bring coop's own findings to the surface. Second, last night's report was of `looper/coop-9`'s commit cc07f51, not of main's 7e8f133.
