# coop

The coop is a tacplus platform service: the fleet's one door to pigeons. A pigeon is a
short-lived worker with its own identity that does one task for one tenant and reports back.
Tenant services (the "dogs") never run pigeons themselves; they ask the coop.

Registered in the tacplus registry as `coop`, id 106.

## The protocol

`proto/shared/pigeon.proto` is the generic pigeon protocol, shared by every pigeon kind:

- `ToPigeon` — the dog's side: a `PigeonTask` (`kind`, `job_id`, an opaque `request`) or an
  `Answer` to a question the pigeon asked.
- `FromPigeon` — the pigeon's side: `Ready`, `Progress`, `Question`, `Result`
  (`PigeonResult` with an opaque `result`, a `Failure`, evidence and recorded steps).

The payloads are bytes: the kind decides their shape. The platform knows the envelope, not the
contents. A kind that needs the Texas 811 ticket flow, say, is a product's business, not the coop's.

## The service

`proto/services/coop.proto`:

- `Coop.CreatePigeon` (S2S, any fleet service) validates the request against the kind in the
  coop's `Config` (domain ceiling, max deadline, max budget, mode), applies the fleet and
  per-tenant live caps and the pause switches, records the run and starts the pigeon. The
  `PigeonTicket` names the run, its thread and the pigeon's SPIFFE id. The same caller with the
  same `idempotency_key` gets the same run back.
- `Coop.CancelPigeon` ends the caller's run `DONE` (or `KILLED`); `Coop.GetPigeon` reads its
  state. A run belongs to the caller that created it; any other caller gets `NotFound`.
- `PigeonMessage` is the thread: an event on `coop.PigeonMessageBus.stream`, one thread per
  run, `TO_PIGEON` from the dog, `FROM_PIGEON` from the pigeon, `FROM_COOP` from the coop.
  `spiffe_id` is stamped by eventbus from the publisher's token, so the coop drops a `TO_PIGEON`
  message from anyone but the run's caller, and answers `PIGEON_GONE` (`never_created`, `discarded`,
  `expired`, `killed`, `failed`) for a run that is not live.
- `PigeonRun` is the audit record, one row per state transition, stored by the Stratum of the
  dog's tenant. The coop inserts each row through Stratum's record write surface
  (`InsertIfAbsent`, routed by the tid in the dog's SPIFFE subject, acked at the record's
  declared durability, `LOCAL`), never by publishing it on the bus (#5). A transition Stratum
  refuses (`UNAVAILABLE` while its redo is unreachable) changes nothing and is refused to the
  caller; a dog in no tenant gets no run.
- `LiveRun` is the coop's working state, in kernel state (`CoopState.runs`), keyed by run id.

Run ids are ULIDs; the thread id is the run id.

## Modes

`Config.mode`:

- `MODE_MOCK` — no Job and no identity: the coop itself is the pigeon. On the dog's first task
  it says `Ready`, marks the run `RUNNING`, then answers with the kind's `mock_result`, a `pigeon.FromPigeon` in the coop's config (or an
  `OK` result when the kind has none). This is slice 1 and what the proof fleet runs.
- `MODE_JOBS` — a Kubernetes Job per pigeon with a minted identity. Not built yet; the coop
  refuses the mode rather than pretending.

A periodic tick ends runs past `deadline_ms` (`DEADLINE`) and runs that did not report `Ready`
within `ready_timeout_ms` (`FAILED`). Setting `paused` or `paused_tenants` kills the live runs
it covers.

## Layout

- `internal/coop` — the handler and the run lifecycle, with tests that need neither Kubernetes
  nor a running fleet.
- `cmd/coop` — wiring: the message publisher, the record plane client, the subscription to the
  coop's own topic, the state client, the tick loop.
- `tacplus/` is generated by `tacplus build` and not committed. `tacplus.yaml`'s `tacplus:` key is the
  compiler line it is generated with.

## Gates

`just gates` regenerates `tacplus/`, checks that generation left every tracked file alone and that
`go.mod`/`go.sum` are tidy for it, then runs `gofmt`, `go build`, `go vet` and `go test` over the module, and
the release scripts' tests (`ci/release_test.sh`).

## Releases

coop is released by version, `vMAJOR.MINOR.PATCH`, and fleets pin a release line (`MAJOR.MINOR`;
tacplus-dev/tacplus#180). It stays on `0.x` until SeaBeam's launch, when `1.0.0` is cut: on `0.x` a minor may
break, a patch never does. A fix merged to main is released as a patch, a feature as a minor, by the run that
merged it. Patches to an older line are tagged on its `release/MAJOR.MINOR` branch.

To cut a release, tag the commit on main (or on the line's `release/MAJOR.MINOR` branch) and push the tag:

```sh
git tag -a v0.1.1 -m "coop 0.1.1: <what changed>" <commit>
git push origin v0.1.1
```

The tag starts `.github/workflows/release.yml`. It runs `just gates` on the tag in the build image
`tacplus.lock` pins (`ci/build-image.sh`), builds `coop` and the launcher for each platform and the
`Dockerfile` over them (labelled with the version and the commit), and pushes
`ghcr.io/tacplus-dev/coop:X.Y.Z` with `GITHUB_TOKEN`. It moves the line tag `X.Y` only when this is the line's
highest release, so the line tag never moves backwards and a patch on one line never moves another
(`ci/release-tags.sh`). Then it creates the GitHub release with the commits since the previous release
(`ci/release-notes.sh`), marked Latest only when it is the highest release of all (`ci/release-latest.sh`). A
pre-release (`vX.Y.Z-rc.N`) gets only its own image tag. The image is built for `PLATFORMS` in the workflow:
`arm64`, what the fleets run on. amd64 is off, as in the fleets; `arm64 amd64` builds both, one image. The
package is public, so pulls need no credential.

Run the workflow by hand (`gh workflow run release.yml -f version=vX.Y.Z`) for a dry run: it builds the
version (tagging this commit locally if the tag does not exist yet) and prints the image tags and the notes
that release would get, and publishes nothing. With `-f publish=true` it publishes an existing tag that has no
GitHub release yet, built from the tag with this workflow's scripts: this is how `v0.1.0`, tagged before the
workflow existed, was published. A tag is never moved or deleted. `just release-test` (part of `just gates`)
tests the scripts.
