# coop

The coop is a tacplus platform service: the fleet's one door to pigeons. A pigeon is a
short-lived worker with its own identity that does one task for one tenant and reports back.
Tenant services (the "dogs") never run pigeons themselves; they ask the coop.

Registered in the tacplus registry as `coop`, id 106.

## The protocol

`proto/shared/pigeon.proto` is the generic pigeon protocol, shared by every pigeon kind:

- `ToPigeon` — the dog's side: a `PigeonTask` (`kind`, `job_id`, an opaque `request`) or an
  `Answer` to a question the pigeon asked.
- `FromPigeon` — the pigeon's side: `Ready`, `Progress`, `Question`, `Result`
  (`PigeonResult` with an opaque `result`, a `Failure`, evidence and recorded steps).

The payloads are bytes: the kind decides their shape. The platform knows the envelope, not the
contents. A kind that needs the Texas 811 ticket flow, say, is a product's business, not the coop's.

## The service

`proto/services/coop.proto`:

- `Coop.CreatePigeon` (S2S, any fleet service) validates the request against the kind in the
  coop's `Config` (domain ceiling, max deadline, max budget, mode), applies the fleet and
  per-tenant live caps and the pause switches, records the run and starts the pigeon. The
  `PigeonTicket` names the run, its thread and the pigeon's SPIFFE id. The same caller with the
  same `idempotency_key` gets the same run back.
- `Coop.CancelPigeon` ends the caller's run `DONE` (or `KILLED`); `Coop.GetPigeon` reads its
  state. A run belongs to the caller that created it; any other caller gets `NotFound`.
- `PigeonMessage` is the thread: an event on `coop.PigeonMessageBus.stream`, one thread per
  run, `TO_PIGEON` from the dog, `FROM_PIGEON` from the pigeon, `FROM_COOP` from the coop.
  `spiffe_id` is stamped by eventbus from the publisher's token, so the coop drops a `TO_PIGEON`
  message from anyone but the run's caller, and answers `PIGEON_GONE` (`never_created`, `discarded`,
  `expired`, `killed`, `failed`) for a run that is not live.
- `PigeonRun` is the audit record, one row per state transition, stored by the Stratum of the
  dog's tenant. The coop inserts each row through Stratum's record write surface
  (`InsertIfAbsent`, routed by the tid in the dog's SPIFFE subject, acked at the record's
  declared durability, `LOCAL`), never by publishing it on the bus (#5). A transition Stratum
  refuses (`UNAVAILABLE` while its redo is unreachable) changes nothing and is refused to the
  caller; a dog in no tenant gets no run.
- `LiveRun` is the coop's working state, in kernel state (`CoopState.runs`), keyed by run id.

Run ids are ULIDs; the thread id is the run id.

## Modes

`Config.mode`:

- `MODE_MOCK` — no Job and no identity: the coop itself is the pigeon. On the dog's first task
  it says `Ready`, marks the run `RUNNING`, then answers with the kind's `mock_result`, a `pigeon.FromPigeon` in the coop's config (or an
  `OK` result when the kind has none). This is slice 1 and what the proof fleet runs.
- `MODE_JOBS` — a Kubernetes Job per pigeon with a minted identity, kernel minting it under
  the dog that asked (`<dog>/workloads/pigeon-<run>`). It needs the in-cluster Kubernetes client: a
  coop without one refuses its runs (`FAILED_PRECONDITION`) rather than pretending.

  Where a run's Job, its Secret and so its bootstrap token go (#17): `pigeons_namespaces` maps each
  tenant (`/tenants/<t>`, the dog's token namespace, as `paused_tenants` names it) to its own
  namespace (`tac-<deployment>-<tid>`, which the operator renders with the coop's Role there). Once it
  has entries, a tenant with none is refused at `CreatePigeon` (`FAILED_PRECONDITION`, naming it):
  nothing falls back to a shared namespace. While it is empty, `pigeons_namespace` holds every Job
  (the one-namespace layout). A run keeps the namespace it started in (`LiveRun.job_namespace`), so a
  config change never moves a live run; on start the coop reconciles every namespace it may have
  pigeons in, and one it may not list is skipped, its runs left alone. In each, the coop needs
  `jobs` create, get, list and delete and `secrets` create and delete.

A periodic tick ends runs past `deadline_ms` (`DEADLINE`) and runs that did not report `Ready`
within `ready_timeout_ms` (`FAILED`). Setting `paused` or `paused_tenants` kills the live runs
it covers.

## Layout

- `internal/coop` — the handler and the run lifecycle, with tests that need neither Kubernetes
  nor a running fleet.
- `cmd/coop` — wiring: the message publisher, the record plane client, the subscription to the
  coop's own topic, the state client, the tick loop.
- `tacplus/` is generated by `tacplus build` and not committed. `tacplus.yaml`'s `tacplus:` key is the
  compiler line it is generated with.

## Gates

`just gates` regenerates `tacplus/`, checks that generation left every tracked file alone and that
`go.mod`/`go.sum` are tidy for it, then runs `gofmt`, `go build`, `go vet` and `go test` over the module, and
the release scripts' tests (`ci/release_test.sh`, `just release-test`: the image tags a release gets, Latest,
its notes and the image build, against scratch repositories and a fake docker).

## Releases

coop is released by version, and fleets pin a release line, `MAJOR.MINOR`, which is always that line's
highest patch ([tacplus#180](https://github.com/tacplus-dev/tacplus/issues/180)). Versions are `0.x` until
SeaBeam's launch (2026-12-01), when `1.0.0` is cut; on `0.x` a minor may break, a patch never does.

A change merged to main is released by the same run that merged it: a fix as the next patch, a feature as the
next minor. To cut one, from the commit to release (a green commit of main):

```sh
git tag -a v0.1.4 -m v0.1.4   # vMAJOR.MINOR.PATCH; a patch to an older line is tagged on release/MAJOR.MINOR
git push origin v0.1.4
```

The tag runs [release.yml](.github/workflows/release.yml), on an arm64 runner: the gates on the tag, in the
build image its `tacplus.lock` pins ([ci/build-image.sh](ci/build-image.sh)), the static `coop` binary for
each platform ([ci/release-binaries.sh](ci/release-binaries.sh)), then the Dockerfile, with the
[launcher](https://github.com/tacplus-dev/launcher) it runs under (the release `LAUNCHER_VERSION`, each
binary pinned by the sha256 of that release's `checksums.txt`; its health probe is the chassis's plaintext
`health_probe_port`, 8444: #14; release.yml still builds a launcher from source at `LAUNCHER_COMMIT` into the
build context, which the Dockerfile no longer reads, until a person with the `workflows` permission removes it), as
`ghcr.io/tacplus-dev/coop:<version>` for linux/arm64 ([ci/release-image.sh](ci/release-image.sh); amd64 is off,
as in the fleets: `PLATFORMS` in release.yml turns it on), labelled with the version and commit
(`org.opencontainers.image.version`, `.revision`). `:<MAJOR.MINOR>` moves to it only when it is the line's
highest patch, so the line tag never goes backwards and no other line moves ([ci/release-tags.sh](ci/release-tags.sh)).
The GitHub release carries the binaries (`coop-linux-<arch>`, `SHA256SUMS`) and the commits since the previous
release ([ci/release-notes.sh](ci/release-notes.sh)), and is marked Latest only when it is the highest release
of all ([ci/release-latest.sh](ci/release-latest.sh)). A pre-release (`v0.2.0-rc.1`) publishes only its own
tag. The package is public, and the workflow's last step pulls the image with no credential to prove it.

Running the workflow by hand publishes a tag that already exists, as its push would have
(`gh workflow run release.yml -f version=v0.1.0 -f publish=true`; v0.1.0 to v0.1.3, tagged before the
workflow existed, were published this way, highest first). Without `publish` it is a dry run
(`gh workflow run release.yml -f version=v0.1.4`): it builds the tag, or this commit tagged locally as a
version not tagged yet, prints the image tags and notes that release would get, and publishes nothing. A
looper's token cannot dispatch a workflow (no `actions: write`), so it sends the same as the
`repository_dispatch` event `release`:

```sh
gh api repos/tacplus-dev/coop/dispatches --input - <<'EOF'
{"event_type": "release", "client_payload": {"version": "v0.1.0", "publish": "true"}}
EOF
```

The scripts are tested by `ci/release_test.sh`, in `just gates`.
